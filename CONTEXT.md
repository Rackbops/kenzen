# kenzen -- context

The orientation ledger for this repo: the domain vocabulary and the toolchain/CI mechanics a
future session would otherwise re-derive. `CLAUDE.md` holds the working rules (layout, style,
gotchas) and is not restated here. The design and delivery plan live under
[`docs/plans/v1/`](docs/plans/v1/) (`design.md`, `plan.md`). Claims below are marked **[code]**
(true of what is built now) or **[design]** (specified in `design.md`, not yet implemented).

## Domain vocabulary **[design]**

Source of truth: `design.md` sections 1-2, 4-6. Cite it, not this summary, when precision
matters.

- **Snapshot** -- one ingest of Tooling's `software-inventory.json` + `software-report.json`.
  Ingest is additive: nothing is overwritten, history is the point.
- **Item** -- one piece of software in one repo, joined from the inventory + report by
  `repo|kind|name|source`: its role, pinned version, latest available, gap, and advisories.
- **Decision** -- a human's call on one item: `skippedVersion`, `remindAt`, `approvedVersion`,
  or `acknowledgedAdvisories`. Semantics copied from the Discord bot's plugin-update flow
  (`rackbops-discord-bot/src/plugins/updates.ts`): a skip is silent until the target is
  strictly newer than it; a reminder is silent until it passes, then surfaces once.
- **The soundness line** -- the one-line per-repo summary on `GET /api/repos` (design.md
  section 6): counts by role, by gap, by advisory status, and the Dependabot read-back.

## Workspace & toolchain **[code]**

- **pnpm workspace** -- members are `packages/*` (`pnpm-workspace.yaml`). Shared dev deps
  (`typescript`, `vitest`, `@types/node`) are pinned once in the workspace **`catalog:`** and
  referenced as `catalog:` per package.
- **Each package** carries `package.json` (`private`, `type: module`, scripts), a
  `tsconfig.json` that `extends ../../tsconfig.base.json` (adding `rootDir: src` /
  `outDir: dist` and `include: ["src"]`), and `src/`.
- **Per-package scripts:** `typecheck` = `tsc --noEmit`; `test` = `vitest run`. **Root
  scripts** delegate: `typecheck`/`test` run `pnpm -r ...`; `lint`/`format` run Biome;
  `check` = `biome check .` + `-r typecheck` + `-r test`. No `build`/`-r build` step yet --
  none of the three packages import another one until K4-2 onward.
- **`tsconfig.base.json`** -- strict, `nodenext` module/resolution, ES2023, plus
  `noUncheckedIndexedAccess`, `noImplicitOverride`, `verbatimModuleSyntax`, `isolatedModules`,
  `resolveJsonModule`. Copied verbatim from `Rackbops/artifact-console` (design.md section 3).
  The nodenext `.js`-extension rule for relative imports is in `CLAUDE.md`.
- **Generated vs. authored:** `pnpm-lock.yaml` is generated by pnpm and **committed** (CI
  installs `--frozen-lockfile`). `dist/` is generated by `tsc` and **gitignored**.

## CI lanes **[code]**

The PR **`tests`** lane (`test.yml`) runs on the org **`disposable`** self-hosted pool --
permitted since this repo is private (Tooling#437's rule; a public repo must never attach a
self-hosted runner). `push-notify.yml` delegates to `roshne/addon-ci`, carries an explicit
fork guard, and passes `DISCORD_PUSH_WEBHOOK` explicitly rather than via `secrets: inherit`.
Both properties -- plus the disposable-pool runner input -- are guarded by
`packages/server/src/ci-hygiene.test.ts`, which reads the workflow files as text rather than
taking on a YAML-parser dependency for a handful of regex checks.

**`image-ratchet.yml`** (K4-6, Tooling#478) builds the real image on the **`docker`** DinD slot
(a pull-request check, blocks merge), boots it with an empty config, and asserts `/healthz`
(`{ok, version, apiVersion:1}`) and the SPA (`scripts/assert-image.mjs`, simplified from
`Rackbops/artifact-console`'s own copy -- no import-map/plugin ABI to pin here yet). The
assertion logic is separately unit-tested against fixture servers in
`packages/server/src/image-assert.test.ts`, so it also runs on the plain test lane with no
Docker. **`release.yml`** publishes multi-arch (amd64/arm64) to `ghcr.io/rackbops/kenzen` on a
`v*` tag, on `ubuntu-latest` (not the disposable pool -- buildx/QEMU needs GitHub-hosted
Docker), version-pinned to `packages/server/package.json` by `scripts/version-tag.mjs`
(`packages/server/src/version-tag.test.ts` unit-tests the pin). `ci-hygiene.test.ts` guards
each workflow's own applicable properties, not a uniform set across all four: `image-ratchet.yml`
has no secrets and no fork-guard to check (self-hosted with no fork-guard is this repo's existing
`test.yml` convention already), so only its DinD runner label is asserted; `release.yml` runs on
`ubuntu-latest`, not the DinD label, so only its fork-guard, GITHUB_TOKEN-not-a-PAT, and
no-`secrets: inherit` properties are asserted.
